# VetMaster 2.0

منصة امتحانات بيطرية متصلة بـSupabase وتعمل مباشرة على Vercel.

## المزايا

- اختيار عدد الأسئلة: 5 أو 10 أو 20 أو 30 أو الكل.
- مؤقت كامل، مؤقت لكل سؤال، أو بدون وقت.
- اختيار موضوع كامل أو أكثر من مقطع/مرض.
- فلترة الصعوبة: سهل، متوسط، صعب، أو مختلط.
- `Exam Mode` للتصحيح بعد النهاية و`Study Mode` للتصحيح الفوري.
- خلط الأسئلة والخيارات.
- تحديد السؤال للمراجعة والتنقل السريع بين الأسئلة.
- تحليل النتيجة حسب الموضوع.
- بنك أخطاء ذكي: تُضاف الإجابة الخاطئة وتُحذف عند حلها صحيحًا لاحقًا.
- أسئلة مفضلة.
- حفظ تلقائي للمحاولة وإمكانية استكمالها.
- لوحة إدارة حقيقية لإضافة وتعديل وتعطيل وحذف الأسئلة.
- إدارة المواضيع والمقاطع، واستيراد/تصدير ملفات JSON.

## الصفحات

- `admin.html`: لوحة الإدارة وتسجيل دخول المدير.

## إعداد Supabase

1. شغّل `supabase-schema.sql` مرة واحدة في **SQL Editor** عند إنشاء قاعدة جديدة.
2. أنشئ مستخدم المدير يدويًا من **Authentication → Users**.
3. عطّل التسجيل العام، واترك تسجيل الدخول بالبريد وكلمة المرور فعّالًا.
4. ضع `Project URL` و`Publishable key` فقط داخل `supabase-config.js`.

> لا تضع `secret key` أو `service_role key` داخل ملفات الموقع. المفتاح الموجود
> في `supabase-config.js` هو مفتاح Publishable عام، والحماية تتم عبر RLS.

## استخدام لوحة الإدارة

1. افتح `/admin.html`.
2. سجّل الدخول بحساب المدير.
3. أضف الموضوع الرئيسي، ثم المقطع أو المرض.
4. أضف السؤال مع أربعة خيارات وحدد الإجابة الصحيحة.
5. السؤال الفعّال يظهر مباشرة في منصة الامتحان بعد إعادة تحميلها.

يمكنك الضغط على **استيراد JSON** داخل اللوحة لرفع ملف `questions.json` القديم.
الأسئلة المكررة بنصها يتم تجاوزها.

## النشر على Vercel

ارفع جميع الملفات إلى الفرع `main` في مستودع GitHub. مشروع Vercel المرتبط
بالمستودع سيعيد النشر تلقائيًا، ولا يحتاج Build Command لأن المشروع Static.

إذا كانت قاعدة Supabase فارغة أو تعذّر الاتصال بها، تستخدم المنصة
`questions.json` مؤقتًا حتى يبقى الموقع قابلًا للتجربة.
